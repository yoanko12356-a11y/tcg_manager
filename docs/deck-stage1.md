# デッキメーカー 第1段階

2026-11-14。referenceの一覧／編集デザインを基準に、ローカル機能のみ追加。

## 操作

1. ホームまたはヘッダーの「デッキ」→「＋ 新しいデッキ」。
2. 右側で検索し、カードを左の採用カード領域へドラッグすると1枚追加。左のカードを右の検索パネルに戻すと、掴んだその1枚だけを削除。キャンセルや同じ領域内へのドロップでは枚数を変更しない。
3. 左・右いずれの画像クリックでも詳細を開く（クリックでは追加しない）。詳細内の矢印／採用枚数欄でも枚数変更できる。カード上の削除ボタンや検索結果の追加ボタンは置かない。
4. 「☆ 主役に設定」で一覧の代表カードを指定。未設定時は最初の採用カード。最後の1枚を外すと主役指定を解除。
5. 名前・並び替えを編集し、ヘッダー「デッキを保存」。Ctrl/Cmd+Sでも保存。
6. 〈で一覧へ戻り、保存したデッキを選ぶと読み込み。未保存で移動・再読込すると確認。削除にも確認あり。

スマートフォン幅では、採用カードの下に検索を縦積みする。デッキ画面に限定してヘッダーナビを折り返す。既存5画面のCSSは変更していない。

## 保存とルール

- `localStorage.tcg_decks_v1` を使用。`tcg_collection`／`tcg_favorite`は書き換えない。
- 同じブラウザ・同じオリジン（ホストとポート）で一覧から読み込める。localhostと127.0.0.1は別の保存先。ブラウザデータ削除で消える。今回はアカウント同期・ファイルインポート／エクスポートなし。
- 40枚未満／超過も**下書き保存**できる。41枚なら「1枚超過」と赤く表示。40枚は「40枚・ルール未検証」。同名5枚以上も注意表示。殿堂・例外カード等の適法性は判定せず、大会用完成デッキとして認定しない。
- JSON破損・未知の保存形式は上書きせず保存／削除停止。容量不足・別タブでの同一デッキ更新ではエラーを表示し、編集中の内容を保持。
- 自動保存は行わない。

## ファイルとデータ構造

- `deck-core.js`：DOMに依存しない作成・個体追加削除・枚数・並び替え・保存データ検証。
- `deck.js`：一覧・編集・検索・詳細ダイアログ・保存の制御。
- `deck.css`：デッキ画面専用スタイル。新たな外部ライブラリなし。
- `index.html`：デッキ画面、専用ダイアログ、保存ボタンと上記ファイルの読み込み。
- `app.js`：デッキモード遷移・離脱確認、カード読込通知、共有検索述語、編集時のヘッダー検索連携。

```json
{
  "schemaVersion": 1,
  "decks": [{
    "schemaVersion": 1,
    "id": "UUID",
    "name": "デッキ名",
    "format": "standard",
    "coverCardKey": "id:123",
    "cards": [{"id": "copy-UUID", "cardKey": "id:123"}],
    "cardSnapshots": {"id:123": {"id": 123, "name": "正式カード名", "image_url": "…", "product_code": "…", "cost": ["3"]}},
    "layout": {"order": ["copy-UUID"], "positions": {}},
    "sort": "cost-asc",
    "createdAt": "ISO-8601",
    "updatedAt": "ISO-8601"
  }]
}
```

採用カードは1枚ずつUUIDを持ち、4枚なら4個体を保存・表示。カード識別は現行JSON全件で一意なカード詳細URLを優先し、無い場合のみid、さらに名前を使用する。数値idはスクレイピングで振り直されるため、URLで更新前後の同一カードを追跡する。版違いは別レコード。カードデータ更新時の欠落に備え、名前・画像・コスト等のスナップショットを保存。

`cards`は採用の事実、`layout.order`は表示順、`positions`は将来の自由配置用。コスト順は表示時だけ計算し、保存された順序・個体IDを書き換えない。共同編集・オンライン共有等は未実装。

検索は既存の正規化・統合検索・同面数値条件を`matchesCardSearchFilters`としてメイン検索と共有。文明OR／AND、単色／多色、追加キーワード、コスト／パワー範囲を適用。旧検索・既存ドロワーの並び替えと表示ロジックは維持。デッキ検索は60件ずつ「さらに表示」。

## 検証

```sh
node --check app.js
node --check deck-core.js
node --check deck.js
node --test tests/*.test.cjs
```

- データモデル：4枚の独立個体、版違い、0コスト、ソートでデータ不変、39/40/41枚保存、主役復元、破損データ、容量不足、既存保存キー不変。
- 検索回帰：実データ23,478件について、変更前の検索述語と共有述語を59条件で比較（基準データが変われば件数も変わる）。
- コントローラー：依存パッケージ不要の最小DOMホストで、作成→追加→41枚→主役指定→保存→再読込→削除、未保存移動キャンセル、既存画面遷移、保存失敗、別タブ競合、独立した文明絞り込み。
- 最小DOMテストはブラウザの描画やドラッグ操作、ネイティブdialogの動作・フォーカスを検証するものではない。
- この実装時はブラウザ操作接続が利用できず、実ブラウザでの目視・ドラッグ・タッチ確認は未実施。外部画像の取得も環境に依存する。既存のローカルサーバーから開き、1440×900／390×844で最終目視が必要。

## referenceに合わせた調整（ドラッグ操作）

- デスクトップの採用カードは8列、検索結果は3列。左右をそれぞれスクロールできる固定高の編集領域。
- 右→左で追加、左→右でその個体を削除。ドラッグ中だけ追加／削除の受入れ先を強調。ドラッグ元の画像にはネイティブの画像ドラッグを無効化し、親カードが個体IDを運ぶ。
- カード上の×、右カードの補助ボタン、常時表示の説明・採用バッジを撤去。超過状態は枚数表示の赤色と読み上げ／ツールチップで確認。
- 詳細は右寄せ、円形の閉じるボタン、主役の星、青／ピンクの枚数矢印、属性の表、能力文の枠という構成。
- 一覧は5列の扇形カード表紙を基準にサイズを調整。
- 先の段階で除外したグループ・共同編集・公開範囲・構築提案は追加しない。
- ネイティブドラッグの実ブラウザ・タッチ動作、ピクセル単位での画像一致は、この接続環境では目視未確認。
